# 禅道改造 AI 提示词

本文档不是研究报告，而是给代码改造型 AI 直接使用的任务提示词。

建议使用方式：

1. 先用“总提示词”让 AI 建立全局上下文。
2. 再按“阶段提示词”逐段执行，避免一次性改动过大。
3. 每一阶段都要求 AI 先读代码、再改代码、再输出变更说明和验证结果。

### 版本映射规则

1. 本地大版本 ≈ 禅道 execution

3. project 134 只是范围容器，不是本地大版本对象
4. testtask 用于补充测试任务维度信息
5. build 是本地小版本最核心的禅道锚点

## 六、已确认的真实业务事实

请把下面事实视为需求真相，不要自行推翻：

1. requirements.zentao_req_id 的数字部分可以稳定映射到禅道 story id
   - 例如 r#5604 -> story 5604

2. Survey Master 这条线中，需求和用例关系较稳定
   - 需求详情页适合实时补充 story/testcase 信息

3. Bug 在禅道中更多挂在 execution/build 上，而不是挂在 story 上
   - 所以本地 bug_tracking.requirement_id 必须继续保留
   - 不能依赖禅道 bug 关系反推本地需求归属

4. 构建记录已经能接收打包系统上报
   - 当前接口：/api/admin/build-report
   - 当前后端服务：BuildRecordService.upsert_report()

5. 构建记录中已经存在“收到发包，但本地没有自动生成对应小版本”的真实数据断层
   - 所以需要在 build-report 收包后自动补建小版本

6. 浏览器插件不是最终方案
   - 最终应由系统直接读取禅道 API

7. 每个测试管理系统用户需要绑定自己的禅道账号
   - 并允许后续修改绑定信息
   - token 失效后后端应自动重新申请

## 七、你要完成的改造目标

你需要分阶段实现以下改造：

### 目标 A：数据库与模型扩展

在不破坏旧结构的前提下，为以下对象增加禅道映射字段：

1. software_products
   - zentao_product_id
   - zentao_product_name_cache

2. versions 中的大版本（version_type=MAJOR）
   - zentao_project_id
   - zentao_project_name_cache
   - zentao_execution_id
   - zentao_execution_name_cache

3. versions 中的小版本（version_type=MINOR）
   - zentao_execution_id
   - zentao_execution_name_cache
   - zentao_build_id
   - zentao_build_name_cache
   - zentao_testtask_id
   - zentao_testtask_name_cache
   - 可选：zentao_release_id
   - 可选：zentao_release_name_cache

4. requirements
   - zentao_story_id
   - 可选：zentao_plan_id
   - 可选：zentao_plan_title_cache

5. test_cases
   - zentao_case_numeric_id

6. bug_tracking
   - 如缺失则补齐 story/build/testtask/execution 相关字段
   - 保留 requirement_id 作为本地主归属，不允许删除

7. users 不建议直接硬塞禅道凭据字段
   - 建议新增独立绑定表 user_zentao_bindings

### 目标 B：新增用户与禅道账号绑定能力

新增一套“当前登录用户绑定禅道账号”的后端与前端能力：

1. 新增表 user_zentao_bindings，建议字段：
   - id
   - user_id
   - base_url
   - zentao_account
   - zentao_password_ciphertext
   - zentao_password_iv
   - token_value
   - token_expires_at
   - last_refresh_at
   - last_refresh_status
   - last_error_message
   - created_at
   - updated_at

2. 密码必须加密存储，不能明文，不能只存 hash
3. 后端增加统一的 zentao auth service
4. token 失效时后端自动重新 POST /v1/tokens
5. 绑定信息支持：
   - 查询当前用户绑定
   - 新建/更新绑定
   - 测试连接
   - 清除失效 token

### 目标 C：构建记录自动生成小版本

这是必须实现的核心改造。

当前 build-report 已能收包，因此你要在这个链路上追加“自动归档为小版本”的逻辑。

必须遵循以下规则：

1. 仅 SUCCESS 构建允许自动创建本地小版本
2. version_name 为空时，不创建小版本
3. 先对 version_name 做归一化：
   - 去掉 (64-bit)、(32-bit) 等平台后缀
   - trim 空格
   - 保留 _alpha.1、_BD、_Geofennel 等业务后缀
4. 从 job_name 解析目标本地大版本
   - s4031 -> V4.0.3.1
   - s40311 -> V4.0.3.11
   - s40311-1 -> V4.0.3.11
   - 解析规则建议兼容：^s(\d{3,})(?:[-_].*)?$
5. 如果本地已存在同名小版本，则不重复创建
6. 如果找不到对应父大版本，不要乱挂父级
   - 应记录异常状态，便于后续处理
7. 自动创建的小版本格式必须与当前人工创建的小版本完全对齐
8. 前端构建记录页和后端归档逻辑必须复用同一套 job_name -> major version 解析器

### 目标 D：构建禅道 API 客户端层

新增一套系统级的禅道 API 读取层，不再依赖浏览器插件作为主数据源。

建议拆分：

1. zentao_auth_service
   - 获取 token
   - 刷新 token
   - 按当前用户读取绑定配置

2. zentao_client_service
   - 基础 GET/POST 封装
   - 统一处理 base_url / token / 错误 / 超时

3. zentao_normalizer
   - 把禅道 API 的原始字段转为本地可消费结构

4. zentao_hydrator
   - 在页面/接口返回本地对象时，补充实时禅道详情

### 目标 E：页面展示增强

不要改变页面主流程，只做“信息补齐”。

#### 需求详情 / 我的工作台

补充：
- story 当前状态
- stage
- planTitle
- assignedTo
- testcase 标题
- testcase 最近执行信息

#### 复测 / Stage5 / 特派

补充：
- bug 当前状态
- assignedTo
- execution
- openedBuild
- actions 最新记录

#### 构建记录页

补充：
- 构建记录与本地小版本自动关联状态
- 显示归档结果
- 如果未能自动归档，给出可读原因

#### 报表

报表仍以本地库为主，不要改成全量依赖禅道。
只在 drill-down 或详情弹层中实时补禅道信息。

### 目标 F：逐步废弃浏览器插件

请不要立即删除旧同步代码，而是做成“过渡期并存”：

1. 第一阶段保留插件同步入口
2. 当 API 直读已覆盖主要页面后，再将插件能力降级为兜底
3. 最后再考虑下线：
   - /api/zentao/browser-sync
   - 同步中心页面
   - 插件相关兼容逻辑

## 4. 推荐使用顺序

建议你按这个顺序让 AI 干活：

1. 先发“总提示词”
2. 再发“阶段一提示词”
3. 阶段一完成后，让 AI 自检并修问题
4. 再发“阶段二提示词”
5. 再发“阶段三提示词”
6. 最后发“阶段四提示词”

如果你希望降低 AI 一次性改坏代码的风险，建议一阶段一提交，不要一口气做完整个改造。
