# IPD 5.6 必填日期与工时适配修复

两个问题已完成代码修复和真实禅道复验。修改位于当前工作区，尚未部署到正式服务。

## 日期字段

- 新建 Bug 弹窗增加“截止日期”必填输入，重开弹窗时清空；未选择有效日期时不发送创建请求。
- `POST /zentao/bugs` 增加必填 `deadline`，校验有效日期并按 `YYYY-MM-DD` 传递给禅道；缺失、空值或非法日期在调用远端前被拒绝。
- 任务看板将预计开始和截止日期标为必填；页面检查漏填、非法日期和开始晚于截止的情况。
- `ZentaoTaskMirrorService.create_board_task` 复用需求派发已有的日期校验，在读取绑定、创建远端任务前拦截非法日程。需求批量派发原有日期校验保持有效。
- 前端入口和两个业务模块的资源版本更新，部署后重新加载页面可取得新字段和校验。

部署时前后端应一起更新。直接调用新建 Bug API 的其他客户端也必须提供 `deadline`；系统不会自动替用户指定截止日期。

## 工时操作

- 工时写请求使用专用 45 秒读取超时，连接超时为 10 秒；其他网页请求保持原超时。
- 新增/编辑每次仅发送一个 POST。即使提交超时，也继续执行最多三轮只读核对，轮次等待为 0、0.5、1 秒。
- 新增按提交前后的新增 ID、本人账号、日期、消耗、剩余和工作内容核对；旧记录、他人记录、部分提交和数量不一致都不能判成成功。
- 编辑按同一个工时 ID 核对日期、消耗、剩余及工作内容，避免只改了部分字段却显示成功。
- 多轮回读仍不能确认时，抛出 `outcome_unknown=True`，明确提示先刷新核实、不要重复提交。现有任务服务会停止自动补交和其他写入兜底。
- 删除优先使用已在 IPD 5.6 实测的 `effort-delete-{id}-yes-.html`，补齐删除最后一条工时所需的确认参数。旧版本的 `task-deleteWorkhour-{id}-yes.html` 作为同账号、同一记录 ID 的兼容路径。
- 删除必须回读确认该 ID 消失；无效响应、权限页或读取超时不能被当成空记录列表。无法回读时停止后续删除尝试。
- 删除/编辑仍经现有状态保护服务处理；最后一条工时删除导致禅道重置任务状态时，恢复原任务状态并同步本地镜像，不再调用 finish 生成额外工时。

网络故障仍可能导致操作结果暂时未知。修复后的行为是核对结果并阻止自动重复新增，不会把未知结果直接显示为成功或失败后自动补交。
