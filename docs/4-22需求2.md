请基于现有 APPAuto / 测试管理系统代码，新增“用户个人 AI API Key 配置 + 按当前用户自己的额度调用 n8n + AI结果入库展示”功能。

一、改造目标
1. 不再使用系统统一的 DeepSeek API Key
2. 每个用户都可以在个人设置中配置自己的 DeepSeek API Key
3. 用户触发“AI处理需求”时，系统读取当前登录用户自己的 API Key
4. 调用 n8n webhook 时，将当前用户自己的 api_key 一并传给 n8n
5. n8n 返回结构化 JSON 后，系统按 story_id 分别保存 AI 处理结果
6. 前端在需求列表或需求详情页可点击按钮查看该需求对应的 AI 处理结果
7. 必须保证不同用户之间看不到彼此的 API Key 明文

二、当前约定
1. n8n 侧已经改成通过 HTTP Request 直接请求 DeepSeek API
2. n8n 接收的 payload 中需要新增字段：
{
    "api_key": "<当前用户自己的 DeepSeek API Key>",
    "request_source": "appauto",
    "operator": "<current_user.username>",
    "execution": {...},
    "selected_story_ids": [...],
    "select_all": false,
    "user_note": "",
    "stories": [...]
}
3. n8n 返回格式约定为：
{
    "execution": {
    "id": 1645,
    "name": "s40311"
    },
    "results": [
    {
      "story_id": 6236,
      "title": "需求标题",
      "briefing": "需求测试简报",
      "module": "未提供",
      "scene": "未提供",
      "stage": "developing",
      "case_type": "功能测试",
      "priority": "高",
      "precondition": "前置条件",
      "steps": [
        {
          "step": "步骤内容",
          "expected": "预期结果"
        }
      ],
      "keywords": "关键词1，关键词2",
      "risk_points": ["风险1", "风险2"],
      "questions_to_confirm": ["待确认1", "待确认2"],
      "testcase_template": "可直接复制到禅道建用例页面的模板文本"
    }
    ]
}

三、数据库改造
请新增一张“用户 AI 配置表”，建议命名：
- user_ai_provider_config

字段建议至少包含：
- id
- user_id
- provider_name （默认 deepseek）
- api_key_encrypted
- api_key_masked
- is_enabled
- created_at
- updated_at

要求：
1. api_key 必须加密存储，不允许明文入库
2. api_key_masked 用于前端展示，例如 sk-xxxx***yyyy
3. 每个用户可以有一条当前生效配置
4. 对 user_id 建唯一索引或合理约束

请新增一张“需求 AI 处理结果表”，建议命名：
- story_ai_result

字段建议至少包含：
- id
- story_id
- execution_id
- execution_name
- title
- briefing
- module_name
- scene_name
- stage_name
- case_type
- priority

- testcase_template
- raw_ai_result_json
- ai_status
- ai_error_message
- created_by
- created_at
- updated_at

要求：
1. story_id 建索引
2. 支持同一 story_id 多次生成结果，优先按 updated_at 取最新
3. steps_json / risk_points_json / questions_to_confirm_json / raw_ai_result_json 使用合适的 JSON 类型或文本字段
4. ai_status 至少支持 success / failed

四、后端接口改造
请新增“用户 AI 配置”相关接口：

1. GET /api/user/ai-config
- 返回当前用户是否已配置 DeepSeek key
- 返回 provider_name、is_enabled、api_key_masked、updated_at
- 不返回明文 api_key

2. POST /api/user/ai-config
- 保存或更新当前用户的 API Key
- 入参至少包含：
  - provider_name
  - api_key
- 保存时进行加密
- 返回脱敏后的状态信息

3. POST /api/user/ai-config/validate
- 使用当前用户填写的 API Key 或请求体中的临时 key 去校验 DeepSeek 接口是否可用
- 只返回是否有效和错误信息
- 不记录明文 key 到日志

五、现有 AI 触发接口改造
请修改当前“禅道需求 -> n8n AI处理”的后端逻辑：

1. 触发 AI 时，读取当前登录用户自己的 AI 配置
2. 如果未配置 API Key，返回明确错误：
   - 例如：请先在个人设置中配置 DeepSeek API Key
3. 调用 n8n webhook 时，在原有 payload 基础上增加：
   - api_key: 当前用户自己的明文 key（仅用于本次调用，不能写日志）
4. 调用 n8n 的 HTTP 请求需要较长超时：
   - connect timeout = 10s
   - read timeout = 300s
5. 正确解析 n8n 返回 JSON
6. 遍历 n8n 返回的 results，按 story_id 分别保存到 story_ai_result 表
7. 若某条结果缺少 story_id，则记录 warning 并跳过
8. 若 n8n 返回格式异常，则保存 raw 文本并标记 failed
