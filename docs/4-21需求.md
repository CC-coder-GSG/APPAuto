你现在要基于现有 APPAuto 项目实现一个“仅限我本人使用的 禅道→N8N AI处理功能”。

目标：
1. 利用系统中现有的禅道绑定、token 刷新、ZentaoClient、story hydrate / project execution sync 能力
2. 新增一个后端能力：让我可以先查询禅道 execution 列表，再查询某个 execution 下的 stories，再选择部分或全部 stories，把详细数据整理后 POST 给 n8n webhook
3. 这个功能暂时只允许我的账号使用，其他用户访问直接 403
4. 第一版不要直接集成 OpenAI SDK，不要在本系统里做 AI 推理，只负责整理数据并转发给 n8n
5. 保持现有项目代码风格，优先复用已有服务与依赖，不要重复造轮子

请你先阅读并复用这些已有能力（如果存在）：
- app/api/routes/zentao_binding.py
- app/api/routes/zentao_version.py
- app/api/routes/zentao_hydrate.py
- app/services/zentao_auth_service.py
- app/services/zentao_client_service.py
- app/models/user_zentao_binding.py
- 项目中所有与 zentao、execution、story、hydrate、binding 相关的 service / route / schema

请实现以下内容：

一、后端新增路由
新增文件：
- app/api/routes/zentao_ai.py
- app/services/zentao_ai_service.py
- app/schemas/zentao_ai.py

新增接口：
1. GET /api/zentao/ai/executions
   - 返回当前登录用户可访问的 execution 列表
   - 支持可选参数 project_id；如果不传则按已有绑定和可访问项目逻辑处理
   - 返回字段至少包含：id, name, project, begin, end, status

2. GET /api/zentao/ai/executions/{execution_id}/stories
   - 返回该 execution 下的 stories 列表
   - 返回字段至少包含：id, title, pri, status, stage, assignedTo, product, productName
   - 对返回数据做适度标准化，避免前端难用

3. POST /api/zentao/ai/generate
   - 请求体字段：
     - execution_id: int
     - story_ids: list[int] = []
     - select_all: bool = false
     - user_note: str = ""
   - 逻辑：
     1. 校验当前用户是否是允许使用该功能的人，不是则返回 403
     2. 读取当前用户的禅道绑定并获取有效 token
     3. 如果 select_all=true，则自动查询 execution 下全部 stories
     4. 对每个选中的 story 调用详情接口，拿到完整 story 数据
     5. 组装标准 payload
     6. 读取环境变量中的 n8n webhook 地址与可选鉴权 token
     7. POST 到 n8n
     8. 返回 n8n 的响应结果给前端

二、标准 payload 结构
发送给 n8n 的 payload 请整理为统一 JSON，结构参考：

{
  "request_source": "appauto",
  "operator": "<current_user.username>",
  "execution": {
    "id": 1790,
    "name": "xxx"
  },
  "selected_story_ids": [5983, 6290],
  "select_all": false,
  "user_note": "xxx",
  "stories": [
    {
      "id": 5983,
      "title": "xxx",
      "pri": 1,
      "status": "active",
      "stage": "developed",
      "product": 15,
      "product_name": "xxx",
      "assigned_to": "...",
      "opened_by": "...",
      "spec_html": "...",
      "actions": [...]
    }
  ]
}

要求：
- 保留 story 的关键原始信息
- 对 assignedTo/openedBy/reviewedBy 等嵌套对象适度扁平化
- spec 保留 html 原文，同时可额外补一个纯文本字段 spec_text（如你认为有必要）
- actions 保留关键字段：id, actor, action, date, desc, comment, extra

三、只允许我本人使用
请增加一个非常简单但可靠的后端限制：
- 从当前登录用户中判断 username/account/id
- 只有指定用户可以使用这个模块
- 建议用配置项，例如 APP_ZENTAO_AI_ALLOWED_USER_IDS 或 APP_ZENTAO_AI_ALLOWED_USERNAMES
- 未命中直接返回 403
- 前端即使隐藏入口，后端也必须做强校验

四、配置项
在配置中新增：
- N8N_ZENTAO_AI_WEBHOOK_URL
- N8N_ZENTAO_AI_WEBHOOK_TOKEN（可选）
- APP_ZENTAO_AI_ALLOWED_USER_IDS 或 APP_ZENTAO_AI_ALLOWED_USERNAMES

并补充到 .env.example

五、前端
请新增一个最小可用前端入口，只给允许用户显示：
- 一个页面或面板
- 先加载 execution 列表
- 选择 execution 后加载 stories
- 支持勾选部分 stories 或选择全部
- 支持填写 user_note
- 点击按钮后调用 /api/zentao/ai/generate
- 展示返回的简报 / 测试用例 / 原始返回 JSON

注意：
- 前端隐藏入口只是体验优化，真正权限控制必须在后端
- 第一版界面可以朴素，但要能用

六、代码要求
- 优先复用现有 ZentaoClient / auth / binding / hydrate 能力
- 不要重复写 token 刷新逻辑
- 不要把密码明文返回给前端
- 代码尽量清晰，函数职责明确
- 需要的 schema、service、route、config 一并补齐

- 给出关键文件的完整代码
