# 最终测试实时协作

最终测试需求新增“正在测试”勾选项。卡片标题处展示每个人的状态，折叠后仍可见：黄色为正在测试，绿色为已测试完成。完成后清除本人的正在测试状态并隐藏该按钮；取消完成后恢复按钮，默认未开始。不同人员互不覆盖。多任务需求继续按本人所有关联任务完成情况汇总。

## 实时更新

- 数据库提交成功后广播人员姓名、需求及状态。其他浏览器直接替换标签，不等待 400ms 防抖或工作台查询，也不刷新整页。
- 修复同步工作线程无法唤醒 SSE 事件循环的问题，避免等待最长约一秒的轮询周期。
- 加载中的旧 HTTP 响应合并请求期间收到的实时状态，防止标签回退。
- SSE 连接恢复后补查工作台；服务重启后发现浏览器游标超过新事件计数时重置游标。
- 禅道关联任务仍先确认远端操作成功，再保存并广播完成状态。网络或禅道慢时不能承诺点击瞬间即完成；失败不广播虚假的成功状态。

## 数据库与部署

使用现有 SQLite 数据库，新增 final_test_records.testing，启动时自动补列，旧记录保留。部署后需重启 Windows 服务并刷新浏览器。

按需求、人员唯一键执行原子 upsert，只更新本次提交的字段；完成状态阻止迟到的正在测试请求。状态和本地审计在同一短事务内提交，远程请求不置于新增写事务内。前端保存期间禁止同需求重复提交。不增加高频数据库轮询。

当前 SSE 总线是进程内广播，实时链路要求单应用进程。若 Windows 服务配置多个 worker 或多个服务实例，应改用共享事件总线（例如 Redis），否则跨进程事件不能保证即时送达。本次未变更现场服务配置或部署。

## 验证

后端覆盖多人共享状态、迟到请求、SQLite 并发原子更新、旧库迁移、关联任务和查询数量，以及后台线程同时唤醒多个 SSE 连接、服务重启游标恢复。

浏览器覆盖勾选与完成按钮、他人实时标签无需额外查询、姓名转义、旧响应不能覆盖实时标签、重连补齐，以及滚动位置和展开状态保留。
