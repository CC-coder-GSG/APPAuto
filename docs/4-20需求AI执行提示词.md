## 现状判断

在动手前，请先接受以下约束和事实：

### 1. `stage5` 目前已经是固化内部模块名，但本轮目标是逐步统一改名

当前仓库里，`stage5` 已经出现在：

- 前端 tab key
- 前端模块文件名
- 前端命名空间
- 后端路由
- 后端 service / 函数命名
- 状态管理
- 文档说明

这说明它不是一个可以随手替换的小字符串。

但这次需求已经明确提出：

- 用户可见界面不要再叫 `Stage5`
- 内部模块之后也不要再叫 `Stage5`

因此本轮要做的是：

- 以“整体测试”为统一名称
- 对内部命名做有计划的重命名
- 必要时保留兼容层
- 不能无脑全仓库替换 `stage5`

建议新的统一命名：

- 中文展示名：`整体测试`
- Python 命名：`overall_test`
- 前端文件 / tab key / 路由 slug：`overall-test`

### 2. 整体测试页目前以本地库为主，不应改成实时依赖禅道

当前整体测试页已经是“先读本地，再后台静默同步”的模式。

请继续保持这个原则：

- 页面主数据源是本地 `bug_tracking`
- 禅道是远端事实源和动作执行源
- 不要把搜索和筛选做成每次都直接请求禅道

### 3. 当前整体测试页还没有真正的状态筛选和编号搜索

现状是：

- 有分页
- 有大版本切换
- 有同步按钮
- 没有状态筛选控件
- 没有编号模糊搜索控件

所以这两个需求不能只在当前页前端临时处理，应该优先补到后端查询能力里。

### 4. 当前仓库没有现成的“禅道 Bug 搜索”客户端方法

目前有：

- 本地 Bug 精确查询
- 禅道单个 Bug 获取
- 禅道创建 / 指派 / 激活 / 关闭 / 删除
- 禅道页面 JSON 元数据获取

目前没有现成的：

- 禅道 Bug 列表搜索客户端方法

因此不要假设“现有代码已经能直接调用禅道 Bug 搜索接口”。

如果你后续确认禅道有稳定搜索接口，可以新增适配，但不能默认依赖它。

### 5. 新建禅道 Bug 页已经有基础元数据能力

当前创建禅道 Bug 相关逻辑已经支持：

- 获取执行列表
- 获取用户列表
- 获取 builds
- 获取模块
- 获取 stories
- 根据 execution 重新拉取 meta

因此这块优先复用现有 `/zentao/bugs/create-meta`，不要重造一套平行接口。

## 本轮总目标

请完成以下 5 项改造：

### 目标 1：整体测试页增加“Bug 状态筛选”

要求：

- 支持至少筛选：
  - `active`
  - `closed`
- 支持多选
- 支持“激活 + 已关闭”组合筛选
- 筛选结果要影响：
  - 列表
  - 分页
  - 顶部统计

建议实现：

- 给整体测试 overview 接口增加查询参数，例如：

- 前端只负责传参和渲染

不要做成：

- 前端只对当前页数据做临时过滤

- 根据输入的编号搜索 Bug

- 搜索词应至少能匹配：
  - `bug_id`
  - `zentao_bug_id`
- 例如输入：
  - `290`
  - `b#290`
  - `29009`
  都应能尽量命中对应记录

建议实现：

- 仍然扩展整体测试 overview 接口
- 增加 `keyword` 查询参数
- 后端做本地模糊匹配

如果你后续验证到禅道存在稳定搜索接口：

- 可以补充“远端补查”能力
- 但不能作为页面默认依赖

### 目标 3：统一去掉 `Stage5/stage5` 命名，包括内部模块

要求：

- 页面标题

- 前端模块文件名
- 前端函数名
- 前端 tab key
- DOM id

- 中文：`整体测试`
- 英文内部命名：`overall_test` / `overall-test`

注意：

- 不要无序全量替换
- 必须先梳理引用链和重命名映射
- 如有必要，保留兼容层
- 但新的主入口不能再继续叫 `stage5`

### 目标 4：新建禅道 Bug 页的“指派给”改成更好用的下拉选择

要求：

- UI 体验更接近“下拉选择”
- 支持按姓名/账号搜索
- 选择某人后，输入框中显示姓名
- 但提交给后端时仍然传账号

建议实现：

- 改成 combobox 风格

- 只显示账号，看不到姓名

### 目标 5：新建禅道 Bug 页的小版本倒序显示，并按执行联动

  - 列表重新加载
