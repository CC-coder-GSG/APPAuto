# 4-17 服务器发布与验收清单

## 一、发布前准备

1. 确认服务器当前服务名、部署目录、Python 虚拟环境路径。
2. 确认线上数据库文件真实路径，不要使用本地附件库替代生产库。
3. 备份以下内容到带时间戳的目录：
   - `app_auto.db`
   - `.env`
   - 当前发布代码目录
4. 记录当前版本信息：
   - Git 分支
   - Git 提交号
   - 服务启动命令或 Windows 服务配置

建议备份目录示例：

```powershell
$ts = Get-Date -Format "yyyyMMdd_HHmmss"
New-Item -ItemType Directory -Force -Path "D:\APPAuto\backup\$ts" | Out-Null
Copy-Item "D:\APPAuto\app_auto.db" "D:\APPAuto\backup\$ts\app_auto.db"
Copy-Item "D:\APPAuto\.env" "D:\APPAuto\backup\$ts\.env"
```

## 二、代码发布步骤

1. 停服务，避免修数过程中仍有新写入：

```powershell
sc stop APPAutoService
```

2. 进入部署目录并更新代码：

```powershell
cd /d D:\APPAuto
git pull
```

3. 安装依赖：

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

4. 先执行基础语法校验：

```powershell
.venv\Scripts\python.exe -m compileall app scripts\fix_417_time_data.py scripts\check_stage5_other_records.py
node --check frontend\js\tabs\stage5.js
```

## 三、时间修复执行步骤

1. 先跑 dry-run，只看统计，不改数据：

```powershell
.venv\Scripts\python.exe scripts\fix_417_time_data.py --log-file logs\fix_417_time_dry_run.log
```

2. 核对输出重点：
   - `safe_shift_total_rows` 是否符合预期
   - 是否明确列出了 `zentao_close_date`、`zentao_remote_updated_at` 为“需重新同步覆盖”
   - 是否没有误包含 `field_test_records.start_time/end_time`

3. 确认无误后再真正执行：

```powershell
.venv\Scripts\python.exe scripts\fix_417_time_data.py --apply --clear-zentao-token-cache --log-file logs\fix_417_time_apply.log
```

4. 修复完成后，启动服务：

```powershell
sc start APPAutoService
```

5. 服务启动后，执行一次禅道全量同步。
   - 目的：回填 `zentao_close_date`、`zentao_remote_updated_at` 等不应直接平移的禅道字段
   - 同时重新生成 token 缓存

## 四、页面验收清单

### 1. 时间类验收

1. 活动日志：新增记录时间是否为东八区本地时间。
2. 整体测试 Stage5：同步时间、关闭时间、关闭人展示是否正常。
3. 反馈、需求、报表、复测相关页面：最新新增或更新记录时间是否正常。
4. 不要只看旧数据，也要新建一条数据验证“止血”是否生效。

### 2. Stage5 验收

1. 进入具体大版本后，确认页面可正常加载。
2. 每条 Bug 操作列应能看到：
   - `编辑`
   - `删除`
   - `展开`
   - 禅道 Bug 还应有 `预览`
3. 点击 `展开` 后，确认详情区正常显示：
   - 其他人闭环记录
   - 无记录时显示“暂无其他测试人员闭环记录”
   - 禅道关闭备注
   - 禅道状态、指派、关闭人、关闭时间、同步时间
4. 点击 `预览`，确认禅道 Bug 详情弹窗可打开，且步骤、附件、流转记录可显示。
5. 选择已配置 `zentao_execution_id` 的大版本时：
   - 本地“新增问题”区应自动隐藏
   - “新建禅道Bug”可正常使用
6. 选择未配置 `zentao_execution_id` 的大版本时：
   - 本地“新增问题”区应显示

### 3. 禅道创建 Bug 验收

1. 打开 `新建禅道Bug` 弹窗，确认字段完整：
   - 标题
   - 严重程度
   - 优先级
   - 指派给
   - 模块
   - 影响版本
   - Bug 类型
   - 关联故事
   - 复现步骤
2. 提交成功后，确认：
   - 页面提示创建成功
   - Stage5 列表中出现新 Bug
   - 禅道内实际创建成功且字段正确

### 4. 指派人加载验收

1. 打开指派弹窗，确认指派人列表能正常加载。
2. 如果失败，优先检查：
   - 当前账号禅道绑定是否有效
   - 禅道页面接口返回是否为双层 JSON
   - token 是否过期

## 五、回滚方案

如果发布后出现异常，按以下顺序回滚：

1. 停服务：

```powershell
sc stop APPAutoService
```

2. 回退代码到上一个稳定提交：

```powershell
git reset --hard <上一稳定提交号>
```

3. 恢复数据库备份：

```powershell
Copy-Item "D:\APPAuto\backup\<时间戳>\app_auto.db" "D:\APPAuto\app_auto.db" -Force
```

4. 启动服务：

```powershell
sc start APPAutoService
```

注意：

- 如果只是前端显示异常，优先只回退代码，不要先回滚数据库。
- 如果已经执行过 `--apply` 且数据结果异常，必须用备份库回滚，不建议手工反向修数。

## 六、建议执行顺序

1. 备份数据库和配置
2. 停服务
3. 拉代码并安装依赖
4. 编译校验
5. dry-run 时间修复
6. apply 时间修复
7. 启服务
8. 做一次禅道全量同步
9. 按页面清单冒烟验收
10. 记录发布结果和最终提交号
