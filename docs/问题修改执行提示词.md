## 必须遵守的设计原则

### 1. 不要推翻现有架构

当前系统已经有：

- 本地数据库缓存
- 禅道版本同步
- Stage5 禅道 Bug 同步
- 禅道 Bug 动作接口

请在此基础上扩展，不要另起一套平行系统。

### 2. 本地库仍然是页面主数据源

页面展示优先读本地数据库。

不要把页面改成每次打开都全量直查禅道。

禅道负责：

- 远端事实状态
- Bug 动作执行
- 版本/需求/Bug 原始数据来源

本系统负责：

- 流程记录
- 闭环记录
- 统计口径
- 审计日志
- 页面秒开体验

### 3. 所有远端动作成功后都要回写本地

包括但不限于：

- 编辑标题
- 关闭 Bug
- 重新激活
- 指派
- 删除
- 后续新增创建 Bug

### 4. 不要只做前端隐藏权限

权限升级后，必须前后端同时生效：

- 前端决定是否显示 tab
- 后端决定是否允许访问接口

### 5. 改造要考虑后续 AI 接入

优先沉淀：

- 稳定 API
- 结构化 JSON
- 审计日志
- 可追踪的同步时间
