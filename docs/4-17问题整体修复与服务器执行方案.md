# 4-17 问题整体修复与服务器执行方案

整理日期：2026-04-17

## 一、先纠正一个前提

`E:\APPAUTO\APPAuto\app_auto.db` 这份库只是你从服务器拷下来的附件，**不能当成生产修复对象**。

它目前只能用于两件事：

1. 本地分析问题范围
2. 本地预演修复脚本，验证脚本不会误伤数据

真正执行修复时，必须以**服务器正在运行的数据库文件**为准，并且脚本必须通过 `APP_DATABASE_URL` 或服务器实际库路径运行。

结合项目现状，当前线上部署方式是：

- Windows Server
- `uvicorn + NSSM`
- SQLite
- 默认数据库：`app_auto.db`

所以这次最稳的方式不是“本地改附件再覆盖”，而是：

1. 在本地完成代码补丁和修复脚本
2. 用附件库先 dry-run
3. 把代码和脚本发到服务器
4. 停服务、备份线上库
5. 在服务器对**线上库原地执行**修复脚本
6. 冒烟验证后再启动服务

## 三、逐项修复建议

## 1. 问题 1：时间错误

### 结论

这是当前优先级最高的问题之一。

### 修复目标

1. **止血**
   后续新写入数据不再慢 8 小时。

2. **修旧**
   已经写错的本地时间数据修正回来。

3. **不误伤**
   禅道同步时间、业务录入时间、token 内部时间不能一刀切平移。

### 代码层做法

把所有“业务写入时间”从 `datetime.utcnow()` 统一收口到一个本地时间函数，例如：

```python
from datetime import datetime

def local_now() -> datetime:
    return datetime.now()
```

重点覆盖：

- 模型默认值 `default=datetime.utcnow`
- 模型更新 `onupdate=datetime.utcnow`
- 服务层手动赋值 `datetime.utcnow()`
- 路由层写时间
- Stage5 的同步缓存时间比较逻辑

### 数据层做法

必须分三类处理：

#### 可以直接 `+8 hours` 的字段

这类是本系统自己生成的时间，适合直接修旧数据。

包括但不限于：

- `created_at`
- `updated_at`
- `handled_at`
- `retested_at`
- `executed_at`
- `changed_at`
- `last_zentao_synced_at`
- `last_zentao_checked_at`

#### 不直接平移，应该重新同步的字段

- `bug_tracking.zentao_close_date`
- `bug_tracking.zentao_remote_updated_at`

处理方式：

1. 先修代码
2. 再触发禅道全量同步
3. 用禅道返回值覆盖本地缓存

#### 不能机械修改的字段

- `field_test_records.start_time`
- `field_test_records.end_time`
- `user_zentao_bindings.token_expires_at`

其中：

- `start_time/end_time` 是人工业务录入时间，不能随便平移
- `token_expires_at` 不建议修旧，建议上线时直接清空 token 缓存重拿

### 服务器执行方式

不要在本地改附件再上传覆盖。

应该在服务器运行一次性脚本，例如：

- `scripts/fix_417_time_data.py --dry-run`
- `scripts/fix_417_time_data.py --apply`

这个脚本必须：

1. 从 `APP_DATABASE_URL` 读线上库
2. 支持 `--dry-run`
3. 输出每张表、每个字段预计影响行数
4. 支持事务回滚
5. 记录日志到文件

## 2. 问题 5：指派人名单加载不出来

### 结论

这是另一个必须立即修的缺陷。

### 根因

禅道页面 JSON 返回双层结构：

```json
{
  "status": "success",
  "data": "{\"users\": {...}, \"builds\": [...]}",
  "md5": "..."
}
```

当前 `get_page()` 拿到外层对象后，直接 `meta.get("users")`，因此永远拿不到实际用户列表。

### 修复方式

在 `app/services/zentao_client_service.py` 的 `get_page()` 里统一解包 `data`。

### 为什么要优先做

这个问题会同时影响：

- 新建禅道 Bug
- 激活 Bug
- 关闭 Bug
- 所有依赖禅道页面 meta 的弹窗

### 服务器执行方式

这是纯代码修复，不涉及历史数据迁移。

上线步骤：

1. 推代码到服务器
2. 重启服务
3. 用真实禅道账号现场验证

## 五、服务器端最方便、最准确的执行方式

## 核心原则

不要手改线上 SQLite。
不要在本地改附件后直接覆盖线上库。
不要把“代码变更”和“数据修复”混在一次黑盒操作里。

最稳的做法是：

### 方案：代码补丁 + 一次性脚本 + SOP

交付物应包含三部分：

1. **代码补丁**
   修 API、前后端逻辑、时间函数、界面行为

2. **一次性脚本**
   专门处理时间历史数据修复

3. **服务器执行 SOP**
   明确停服、备份、dry-run、apply、验证、回滚步骤

---

## 六、推荐服务器上线 SOP

以下路径按 `DEPLOY_WINDOWS.md` 的默认部署假设：

- 代码目录：`D:\APPAuto`
- 服务名：`APPAutoService`
- 数据库：`D:\APPAuto\app_auto.db`

### Step 0：本地先做预演

1. 在本地附件库执行 `--dry-run`
2. 在本地附件库执行 `--apply`
3. 检查结果是否符合预期
4. 确认脚本日志和回滚逻辑可用

本地附件库只做这一步。

### Step 1：服务器停服前备份

```bat
sc query APPAutoService
sc stop APPAutoService
mkdir D:\APPAuto\backup
copy D:\APPAuto\app_auto.db D:\APPAuto\backup\app_auto_before_fix_2026-04-17.db
```

同时记录当前代码版本：

```bat
cd /d D:\APPAuto
git rev-parse HEAD > backup\before_fix_commit.txt
```

### Step 2：更新服务器代码

```bat
cd /d D:\APPAuto
git fetch --all
git checkout <目标分支或提交>
git pull
.venv\Scripts\activate
pip install -r requirements.txt
python -m app.init_db
```

### Step 3：先 dry-run，不直接 apply

```bat
python scripts\fix_417_time_data.py --dry-run
```

dry-run 必须输出：

- 当前连接的数据库路径
- 每张表每个字段拟修改行数
- 不会修改的字段名单
- 重新同步覆盖的字段名单

只有 dry-run 结果符合预期，才执行下一步。

### Step 4：正式 apply

```bat
python scripts\fix_417_time_data.py --apply
```

### Step 5：清理 token 缓存

建议把它并入脚本，或单独执行：

```sql
UPDATE user_zentao_bindings
SET token_value = NULL,
    token_expires_at = NULL;
```

### Step 6：启动服务并重新同步禅道

```bat
sc start APPAutoService
sc query APPAutoService
```

然后用系统功能触发：

- Stage5 全量同步
- 禅道 Bug 元数据加载

把 `zentao_close_date`、`zentao_remote_updated_at` 等字段重新覆盖。

### Step 7：冒烟验证

重点验这几项：

1. 整体测试页同步时间显示正确
2. 禅道指派人下拉能加载
3. 新建禅道 Bug 弹窗字段完整
4. Bug 预览能打开
5. 报表中心按天统计正常
6. 活动日志时间正确
7. 禅道绑定重新获取 token 成功

## 七、回滚方案

如果上线失败，回滚要能在 5 分钟内完成。

### 代码回滚

```bat
sc stop APPAutoService
cd /d D:\APPAuto
git checkout <before_fix_commit>
```

### 数据回滚

```bat
copy /Y D:\APPAuto\backup\app_auto_before_fix_2026-04-17.db D:\APPAuto\app_auto.db
```

### 启服务

```bat
sc start APPAutoService
```
